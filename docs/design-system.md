# TagNote Design System

この文書は、TagNote のページ、レイアウト、UIコンポーネント、表示状態を追加・変更するときの共通基準です。視覚的な統一だけでなく、操作性、アクセシビリティ、レスポンシブ対応までをデザインシステムに含めます。

## 1. 適用方法と信頼できる情報源

UIに影響する作業を始める前に、この文書を全文確認してください。判断の優先順位は次のとおりです。

1. アクセシビリティ、セキュリティ、プロダクト要件
2. このデザインシステムの原則と規約
3. `app/globals.css` のデザイントークンと共通クラス
4. `components/layout/app-shell.tsx` と `components/ui/` の既存実装
5. ページ固有のスタイル

`app/globals.css` は実際にブラウザへ適用されるトークンの実装上の正本です。この文書はトークンの意味と使い方の正本です。両者に差異を見つけた場合は放置せず、意図を確認して同じ変更内で同期してください。

ページ固有の都合で共通ルールを上書きする前に、既存トークンやコンポーネントで表現できないか検討します。同じ視覚パターンが2か所以上に現れたら、再利用可能なコンポーネントまたは共通スタイルへの抽出を検討してください。

## 2. デザイン原則

### 静かで明瞭

コンテンツを主役にし、装飾は情報の階層や操作可能性を伝えるために使います。境界線、影、色を同時に強くせず、通常状態は低コントラスト、選択・フォーカス・主要操作だけを明確にします。

### 親しみのある上質さ

Appleプラットフォームに通じる明快な階層、十分な余白、繊細な半透明表現、自然な反応を参考にします。ただし、Appleの画面、アセット、製品固有の表現をそのまま複製しません。

### 迷わず操作できる

画面ごとの主要操作は原則1つに絞ります。操作の結果、保存状態、読み込み、空状態、失敗、破壊的操作を明示し、ユーザーが現在地と次の行動を判断できるようにします。

### すべての環境で一貫する

ライト／ダーク、デスクトップ／モバイル、ポインター／キーボード、通常／モーション軽減の各環境で同じ情報と操作を提供します。狭い画面では情報を隠すのではなく、優先順位に沿って再配置します。

## 3. カラー

### セマンティックカラートークン

コンポーネントでは、原則としてHEX値ではなく次のCSS変数を使います。

| トークン | ライト | ダーク | 用途 |
| --- | --- | --- | --- |
| `--surface` | `#f7f7f9` | `#111216` | アプリ全体の背景 |
| `--surface-raised` | `#ffffff` | `#191a1f` | カード、入力欄、浮いた面 |
| `--sidebar` | `#f1f1f4` | `#16171b` | サイドバー、モバイルナビゲーション |
| `--ink` | `#18191d` | `#f2f2f4` | 見出し、本文、主要操作 |
| `--muted` | `#65666d` | `#a1a2a9` | 補助本文、通常のアイコン |
| `--muted-soft` | `#95969d` | `#74767f` | メタ情報、プレースホルダー |
| `--hairline` | 8%の境界色 | 8%の白 | 通常の境界線、区切り |
| `--hairline-soft` | 6%の境界色 | 6%の白 | カード内部の弱い区切り |
| `--nav-active` | 白90% | 白7.5% | 選択中のナビゲーション |
| `--nav-hover` | 白62% | 白5% | ホバー、弱い操作面 |
| `--chip` | `#f1f1f4` | 白5.5% | タグや小さなラベルの背景 |

色の使い分けは要素の意味で決めます。例えば、見出しは常に `--ink`、補助文は `--muted`、時刻などのメタ情報は `--muted-soft` を使用します。単に「少し薄くしたい」という理由で新しいグレーを追加しません。

### アクセントカラー

主要な選択・フォーカス・リンクには blue-600 系を使います。カテゴリの分類色は次の10色から選び、色の定義は `lib/memos/category-colors.ts` を実装上の単一の情報源とします。

| 名前 | 基準色 | 薄い背景 | 主な用途 |
| --- | --- | --- | --- |
| Blue | `#5e8bff` | 12% | 仕事、通常の選択、情報 |
| Sky | `#4ca5e0` | 12% | 学習、調査 |
| Cyan | `#2fb7c4` | 12% | 技術、資料 |
| Teal | `#2aa889` | 12% | 習慣、継続的な記録 |
| Lime | `#86a83f` | 12% | 自然、成長に関する分類 |
| Yellow | `#d5a52a` | 12% | 知識、参照情報 |
| Orange | `#ff9f56` | 12–13% | 個人、注意を伴わない強調 |
| Rose | `#e8788d` | 12% | 暮らし、やわらかな分類 |
| Pink | `#d973c5` | 12% | 趣味、関心事 |
| Violet | `#a67cf7` | 12% | アイデア、創造的な内容 |

分類色だけで状態を伝えず、必ずカテゴリ名、選択状態、アイコンのいずれかを併用します。色選択はテキストだけのプルダウンにせず、名称と実際の色見本を並べたラジオグループにします。カテゴリ用のTealやLimeは成功状態を意味しません。エラー／破壊的操作の赤系と成功表示の緑系は、明示的な文言を伴う状態表示に予約します。ヒーローや図版など固有の表現に直接色を使う場合も、ライト／ダーク両方を定義し、他のページへ安易に複製しません。

## 4. タイポグラフィ

標準フォントは `next/font` で読み込む Geist と、Appleシステムフォント、日本語システムフォントのフォールバックです。本文に別のフォントを追加しません。コードやMarkdownのコードブロックには `--font-mono` を使います。

| 役割 | 推奨サイズ | 太さ | 行間・字間 |
| --- | --- | --- | --- |
| ページタイトル | `32–52px`、`clamp()` | 600 | 行間1、字間 `-0.06em` 前後 |
| セクションタイトル | `17px` | 600–650 | 字間 `-0.025em` |
| カードタイトル | `17px` | 600 | 字間 `-0.025em` |
| 本文 | `14–15px` | 400 | 行間 `1.6–1.7` |
| UIラベル | `13–14px` | 500–600 | 通常またはわずかに詰める |
| メタ情報 | `10–12px` | 500–600 | 通常 |
| Eyebrow | `10–11px` | 700 | 大文字、字間 `0.08–0.14em` |

1ページに視覚上の `h1` は1つだけ置き、見出しレベルを飛ばしません。英大文字の Eyebrow は短い補助ラベルに限定し、日本語本文を大文字相当の装飾で過度に分断しません。長文では可読性を優先し、負の字間を本文へ適用しません。

## 5. 余白、サイズ、グリッド

Tailwind CSSの4px刻みを基本単位とします。頻出する間隔は `8px`、`12px`、`16px`、`20px`、`24px`、`32px`、`40–44px` です。任意値は、既存コンポーネントとの整合や視覚補正が必要な場合だけ使用します。

- ページコンテナ: `max-w-[1480px]`、左右 `16px / 24px / 32px / 40px`
- ページ上部: モバイル `28px`、デスクトップ `36–40px`
- 大きなセクション間: `40–44px`
- カード間: `12–16px`
- カード内側: `14–20px`。主要な訴求面のみ `24–32px`
- コントロール高さ: 通常 `40px`、主要なサイドバー操作 `44px`
- アイコン単独操作: 原則 `38–40px` の操作領域を確保

密度を下げるためだけに余白を増やし続けず、同じ階層では同じ余白を使います。入力画面では、コンテンツ幅を読みやすい範囲に制限し、横幅いっぱいの長文を避けます。

## 6. 角丸、境界線、影

角丸は面の大きさと階層に合わせます。

- 小さなラベル、キーヒント: `6–8px`
- ナビゲーション項目、入力、通常ボタン: `10–12px`
- 小型カード、カテゴリカード: `16px`
- メモカード: `20px`
- 大きな訴求面: `24–26px`
- アバター、コンパクトな主要操作: 完全な円

通常カードは `--hairline` の1px境界線と、ごく弱い影を組み合わせます。ホバー時は `2–3px` だけ上昇させ、影をわずかに強めます。すべての面を浮かせず、階層が同じカードには同じ影を使います。強い影、純黒の影、太い境界線はモーダルや重要なオーバーレイなど、明確な理由がある場合に限定します。

半透明と `backdrop-blur` は、固定ヘッダー、モバイルナビゲーション、重なりを表現する訴求面に限定します。通常の本文カードへ多用しません。

## 7. アイコン

共通アイコンは `components/ui/icon.tsx` の `Icon` を使用します。標準サイズは、インライン `15–18px`、主要アイコン `19–20px` です。線幅と端点の表現を揃えるため、同一画面に別スタイルのアイコンセットを混在させません。

- 装飾アイコンには `aria-hidden="true"` を付けます。現在の `Icon` は既定で対応しています。
- アイコンだけのボタンには、動作を表す具体的な `aria-label` を必ず付けます。
- 意味のない絵文字をアイコンの代用にしません。
- 新しいアイコンが必要な場合は既存の線幅、24px viewBox、命名規則に合わせて `IconName` とパスを追加します。

## 8. コンポーネント規約

### ボタン

- Primary: 画面の主要操作。`primary-button` またはアプリシェルの黒い主要ボタンと同じ表現を使い、同一領域に複数置きません。
- Secondary: 表示切替など、主要操作を補助するもの。`secondary-button` を使います。
- Text: 「すべて見る」「管理する」など、セクション内の補助導線。`text-button` を使います。
- Icon-only: 40px前後の操作領域、具体的なアクセシブル名、ホバーとフォーカスを持たせます。
- Destructive: 赤系を使用し、実行前に影響範囲を示します。主要操作の黒と見分けられる文言を併用します。

押せない要素をボタンのように見せません。処理中は二重送信を防ぎ、ラベルまたは近接するステータスで進行中と分かるようにします。ボタンの文字は「保存」「メモを削除」のように、結果が分かる動詞を優先します。

### 入力

入力はラベルを必須とし、プレースホルダーだけで意味を伝えません。通常は高さ40px、角丸12px、`--surface-raised` の背景、`--hairline` の境界線を使います。フォーカスは青い境界と淡い外側リングで表現します。エラーは色だけでなくメッセージを関連付けます。

モバイル検索はアイコンからフォーカス時に入力欄へ展開します。新しい入力も狭い画面でラベル、入力値、エラーが見切れないことを確認します。

### カード

- メモカード: `memo-card` を基準にします。本文を表示する一覧ではタイトル、抜粋、タグ、カテゴリ、更新日時の順序を保ちます。走査性を優先する一覧ではMarkdownをレンダリングせず、書式を除いたプレーンテキストの抜粋を固定行数で表示してカードの高さを統一します。
- カテゴリカード: `category-card` を基準に、分類色はアイコン背景へ控えめに使用します。
- 訴求カード: `overview-card` のような大きなグラデーション面は、1画面に原則1つまでです。

カード全体がクリック可能な場合、内部のメニューなど別操作とフォーカス順が競合しないように実装します。カードの高さを揃えるために内容を不自然に切らず、一覧の走査性と内容の理解のバランスを取ります。

### タグとステータス

タグは `--chip` の背景に `--muted` の文字を使い、小さくても読める余白を確保します。タグ、カテゴリ、状態を同じ視覚表現にせず、タグは `#名前`、カテゴリは色点またはフォルダー、処理状態は明示的なラベルとして区別します。

### フィードバック状態

データを扱うページは、通常表示だけでなく次を同じ視覚言語で用意します。

- Loading: 最終レイアウトに近い控えめなスケルトン。長時間処理では文言も表示
- Empty: 状況を説明する短い見出し、補足、次に行う主要操作
- Error: 何が失敗したか、データが保たれているか、再試行方法
- Success: 操作対象の近くへ簡潔に表示。軽微な操作でモーダルを使わない
- Disabled: 理由が理解できる文脈を用意し、単に薄くするだけにしない

操作完了やページ遷移をまたぐ認証結果には、共通トーストを使用します。画面上部へ最大1件を約4秒表示し、成功はチェック、失敗は警告アイコンと文言を併用します。成功は `status`、失敗は `alert` として支援技術へ通知し、手動で閉じられる40px相当の操作領域を設けます。入力値の修正が必要な検証エラーはトーストへ移さず、対象入力の近くに関連付けて表示します。

## 9. レイアウトとレスポンシブ

共通シェルは `components/layout/app-shell.tsx` を使用し、各ページでサイドバーやヘッダーを再実装しません。

- `< 640px`: モバイル。ヘッダーは64px、検索は展開式、主要操作はコンパクト表示、カードは1列
- `640–1023px`: タブレット。カードは内容に応じて2列、ヘッダー操作を表示
- `>= 1024px`: デスクトップ。272pxのサイドバーと80pxのヘッダー、モバイルナビゲーションは非表示
- `>= 1280px`: 広い画面。メモカードは3列、ページ左右余白は40px

モバイル下部ナビゲーションがコンテンツを隠さないよう、ページ末尾に十分な余白を確保します。固定ヘッダーがアンカー先を隠さないよう `scroll-padding-top` を維持します。新しいページは390pxと1440pxを最低限確認し、横スクロールが発生しないようにします。

## 10. モーション

モーションは状態変化の理解を助けるために使います。通常のホバーとフォーカスは `150–180ms`、大きな画面遷移でも短く保ちます。カードの上昇は最大3px、主要ボタンは最大1pxを基準とします。

常時動く装飾、強いバウンド、大きな拡大は避けます。`prefers-reduced-motion: reduce` ではアニメーションとスムーズスクロールを実質無効化します。機能の理解をアニメーションだけに依存させません。

## 11. アクセシビリティ

- ページごとに固有で説明的なタイトルと `h1` を設定します。
- `header`、`nav`、`main`、`section`、`article` など適切なランドマークを使います。
- キーボードフォーカスを消さず、フォーカス位置を視認可能にします。
- アイコンのみの操作、曖昧なリンク、複数のナビゲーションにはアクセシブル名を付けます。
- 本文と背景はWCAG AA相当のコントラストを目標にします。`--muted-soft` は小さな補助情報に限定し、重要な本文には使いません。
- タップ対象は原則40px以上とし、近接する操作の誤タップを防ぎます。
- ホバーで現れる操作は、タッチ端末とキーボードフォーカスでも利用可能にします。
- フォームのエラー、保存状態、非同期更新は支援技術へ伝わるようにします。
- 200%拡大、長い日本語、空データ、長いタグ名でも情報や操作が欠けないようにします。

## 12. 文言とコンテンツ

ユーザー向け文言は日本語を基本とし、短く自然にします。タイトルは名詞または状態、ボタンは結果が分かる動詞を使います。専門用語を避け、英語の装飾ラベルは意味を補助する範囲に限定します。

- 良い例: 「新しいメモ」「変更を保存」「メモを復元」「もう一度試す」
- 避ける例: 「OK」「実行」「送信」のように、対象や結果が分からない表現

日時、件数、保存状態の表記は同じ画面内で統一します。削除、アーカイブ、ゴミ箱の違いは文言で明確にします。

## 13. 新しいページの基本構成

ページは共通シェルの `main` 内へ描画されるため、ページ側で `main` を重ねません。次の構成を出発点とします。

```tsx
export default function ExamplePage() {
  return (
    <div className="mx-auto w-full max-w-[1480px] px-4 py-7 sm:px-6 sm:py-9 lg:px-8 lg:py-10 xl:px-10">
      <header className="flex flex-col gap-5 sm:flex-row sm:items-end sm:justify-between">
        <div>
          <p className="eyebrow">SECTION LABEL</p>
          <h1 className="mt-2 text-[clamp(2rem,5vw,3.25rem)] font-semibold leading-none tracking-[-0.06em] text-[var(--ink)]">
            ページタイトル
          </h1>
          <p className="mt-3 text-sm leading-6 text-[var(--muted)] sm:text-[15px]">
            このページでできることを簡潔に説明します。
          </p>
        </div>
      </header>

      <section className="mt-11" aria-labelledby="section-title">
        <h2 id="section-title" className="section-title">セクションタイトル</h2>
      </section>
    </div>
  );
}
```

これは固定テンプレートではありません。情報構造に合わせて簡潔にしつつ、コンテナ幅、ページ余白、見出し階層、セクション間隔は揃えてください。

## 14. 実装・レビューチェックリスト

UI変更の実装前:

- この文書と変更対象の既存コンポーネントを確認したか
- 新しいパターンが本当に必要か、既存パターンを再利用できないか
- 通常、読み込み、空、エラー、長い内容の各状態を考慮したか

実装中:

- 色にセマンティックトークンを使用したか
- 既存の文字階層、余白、角丸、影、アイコン表現に沿っているか
- HTMLの意味、アクセシブル名、キーボードフォーカスを保っているか
- モバイルとダークモードを後付けにせず同時に実装したか

完了前:

- 390pxと1440pxで実ブラウザ確認を行ったか
- ライト／ダーク、キーボード、モーション軽減を確認したか
- 長い文言、空状態、エラー状態で崩れないか
- `npm run typecheck`、`npm run lint`、関連テスト、`npm run build` が通るか
- トークンや共通パターンを変更した場合、この文書も更新したか

## 15. デザインシステムの変更

デザインシステムは変更可能ですが、ページ単位で無言に分岐させません。新しいトークン、コンポーネント変種、ブレークポイント、アイコン規約を導入する場合は、既存画面への影響を確認し、この文書と実装を同じ変更で更新します。

意図的な例外は、なぜ既存ルールでは不十分かをコードレビューで説明します。例外が繰り返される場合は、個別スタイルを増やすのではなく共通ルールの見直しを行います。
